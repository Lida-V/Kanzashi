# Kanzashi：生成した髪を毛束で扱う

Kanzashi は Blender のアドオンです。ひとかたまりの髪のメッシュを毛束に分け（毛束ごとに 1 色と 1 本のワイヤー）、色を塗って分け方を直し、ワイヤーで曲げ、毛束ごとの UV を作ります。
このスキルは、エージェントがそれを**いつ・どの順で使い、どこでユーザーに確認するか**を決めます。コードの説明は [README.md](../../README.md) にあります。

以下の `<repo>` は、このリポジトリの場所です（この SKILL.md の 2 つ上のフォルダ）。

## いつ使うか

- 髪が 1 つ（または少数）のメッシュに溶け合っていて、毛束ごとに選ぶ・曲げる・塗ることができないとき。
- 髪の流れを直したい、腕や体に入った毛束をよけたい、と頼まれたとき。
- 髪のテクスチャを作り直す前に、毛束ごとに整った UV が要るとき。

### 工程の位置（決まり）

**頭と髪を別のパーツに分けた段で、テクスチャを貼り直す前に行います。** 順番は次のとおりです。

1. 頭と髪のパーツ分け（髪の形と位置もここで決める）
2. Kanzashi（毛束の検出、塗り直し、曲げ、貫通の確認、毛束ごとの UV）
3. 髪のテクスチャの貼り直し

- 頭と髪がまだ 1 つのメッシュなら、先にパーツ分けをします。検出は渡したメッシュの面をすべてどれかの毛束に入れるので、顔や頭皮の面が混ざっていると、それも毛束になります。
- テクスチャを貼り直した後に行うと、UV が変わるので、貼り直しがやり直しになります。順番が逆のときは、手順 0 でユーザーに伝えてから決めます。
- 検出は毛束の境でメッシュを切るので（頂点が増えます）、できればリグとシェイプキーを付ける前に済ませます。すでにリグが付いた髪でも動きますが、検出の後に骨を動かして、髪が体に付いてくるかを確かめてください。

使わないとき：髪がもう毛束ごとの部品に分かれている。髪カード（板）だけで作られている。Blender が 5.3 より古い。

## 守ること

- **元のファイルを書き換えない。** スクリプトは開いたファイルを保存せず、結果を新しいファイルに出します。出力先がすでにあると止まります。出力の名前を毎回変えてください。
- **ユーザーが塗り直した・曲げたファイルで、検出をやり直さない。** `kanzashi_run.py` は、検出済みの髪の毛束をそのまま残します。`--redetect` は、ユーザーが「最初からやり直す」と言ったときだけ使います。
- **アドオンを入れる・更新するのは、ユーザーの許可を得てから。**
- **毛束ごとの UV を作った髪を、ほかの道具・スキルで分割・結合・UV の作り直しをしない。** パーツ分け、材質ごとの分割、ばらばらの部品への分離、結合、Smart UV・展開のやり直しは、毛束ごとの UV を崩します。Kanzashi は UV を作った髪に印（オブジェクトのプロパティ `kanzashi_uv_lock`）を付けます。ほかの工程が髪に触る前と後に、次を実行します。終了コードが 1（`split`＝分割された、`changed`＝頂点・面が変わった、`uv_changed`＝UV が変わった、`uv_missing`＝UV が無い）なら、その結果を使わず、ユーザーに知らせます。髪のパーツ分けが要るなら、Kanzashi の前に済ませます（工程の位置）。印のある髪をどうしても分けるときは、ユーザーに確認し、分けた後に Kanzashi の UV を作り直します。

```bash
blender -b model.blend --python <repo>/scripts/kanzashi_guard.py -- --report guard.json
```
- 報告の数だけで「できた」と言わない。分かれ方が良いかは、画像を見たユーザーが決めます。
- 毛束の色を塗る作業は、ユーザーが Blender の画面で行います。エージェントが代わりに塗ることはしません（どの面がどの毛束かは見た目の判断です）。
- ワイヤーを曲げるのも、基本はユーザーです。エージェントが動かすのは、体への貫通を直すときだけで、案を示して「AI の案で直す」と言われてから行い、結果を画像で確認してもらいます（手順 5）。

## 流れと、ユーザーに確認する所

★ は、止まってユーザーに確認する所です。確認は 1 回に 1 つ、画像を添えて、選べる形で聞きます。

### 0. 準備

1. Blender の場所と版を確かめます（5.3 以上）。
2. 対象のファイルと、髪のメッシュの名前を調べます。名前か材質の名前に hair・bangs・髪 などを含むメッシュが自動で選ばれます。髪飾りが混ざる、髪が選ばれない、という恐れがあれば `--hair 名前` で指定します。
3. 工程の位置を確かめます（上の「工程の位置」）。髪が頭と別のメッシュになっているか、髪のテクスチャがもう貼り直してあるかを、ファイルと制作の記録で見ます。

★ 頭と髪が分かれていないとき：「先に頭と髪のパーツ分けが要ります」と伝え、パーツ分けが済むまで検出を始めません。
★ 髪のテクスチャがもう貼り直してあるとき：「毛束の UV を作ると、貼り直したテクスチャはそのままでは使えません」と伝えて聞きます。(a) 今の見た目を新しい UV へ写す（手順 6 の張り替え。細部は少し変わります）、(b) Kanzashi の後にテクスチャを作り直す、(c) やめる。

4. アドオンが入っているかを調べます。

```bash
python <repo>/tools/install_addon.py --check
```

★ 入っていない、または版が古いとき：「Kanzashi のアドオンを Blender に入れてよいですか（入れなくても、その場だけパネルを出して使えます）」と聞きます。よければ次を実行します。

```bash
python <repo>/tools/install_addon.py
```

Blender が既定の場所にないときは `--blender パス` を付けます。入れない場合も、この先の手順はすべてできます（パネルは `scripts/kanzashi_panel.py` で出します）。

### 1. 検出と UV（パネルなし）

```bash
blender -b model.blend --python <repo>/scripts/kanzashi_run.py -- --out model_k1.blend --report k1.json
```

最後の行 `KANZASHI {...}` と `k1.json` を読みます。

| 見る所 | 目安 |
|---|---|
| `ok` | false なら止まって、`error` と `check` をユーザーに伝える |
| `hairs[].wires` | 毛束の数。見た目の房の数とかけ離れていないか |
| `hairs[].error` | その髪は外されている。ほかの髪は続いている |
| `check.ok` | UV の検査。false のときは、書き出しと張り替えをしない |
| `check.islands` | UV の島の数。毛束の数よりずっと多いときは、細かい島が多い（限界の節） |

### 2. 確認用の画像

```bash
blender -b model_k1.blend --python <repo>/scripts/kanzashi_preview.py -- --out-dir k1_preview
```

前・後ろ・左・右の 4 枚（毛束ごとの色）と、UV の 1 枚が出ます。エージェントも画像を見て、次を確かめます。

- 1 本の房が、途中で別の色に切れていないか。
- 別々の房が、同じ色でつながっていないか。
- 頭頂の溶け合った所が、房ごとに分かれているか。

★ 画像をユーザーに見せて聞きます。「毛束の分かれ方はこれでよいですか」。選択肢は、(a) このまま進める、(b) 自分で塗って直す、(c) 曲げたい毛束がある、です。気づいた所（例：「左の前の房が 2 色に切れています」）を添えます。

### 3. ユーザーが直す（塗る・曲げる）

(b) か (c) のとき、ユーザーに Blender を開いてもらいます。アドオンが入っていれば `model_k1.blend` を開くだけです。入っていなければ、次で開きます。

```bash
blender model_k1.blend --python <repo>/scripts/kanzashi_panel.py
```

ユーザーに伝えること：

1. サイドバー（N キー）の「Kanzashi」タブを開く。言語はいちばん上の欄で選べます。
2. ① の「自動で登録」を押す。**② の検出はもう押さない**（塗り直しが消えます）。
3. 色を直すなら ③、曲げるなら ④。戻すのは Ctrl+Z。
4. 終わったら、**別の名前で保存**する（例：`model_k2.blend`）。保存したら知らせてもらう。

エージェントは、ユーザーが保存したと言うまで待ちます。

### 4. 直した後の UV と確認

```bash
blender -b model_k2.blend --python <repo>/scripts/kanzashi_run.py -- --out model_k3.blend --report k3.json
```

`hairs[].kept_strands` が true（毛束を残した）であることを確かめます。もう一度、確認用の画像を作ります（手順 2）。

★ 画像を見せて聞きます。「これで毛束と形は決まりですか」。まだ直すなら手順 3 へ戻ります。

### 5. 体への貫通を調べる

毛束が体や腕に入っていないかを、エージェントが調べます。この計算はアドオンには入っていません（Blender の画面では、ユーザーが目で見て分かります。計算は重いので、エージェントの確認用です）。毛束のワイヤーが残っているファイルで行います（形を確定する前）。

まず、何と比べるかを決めます。

```bash
blender -b model_k3.blend --python <repo>/skills/kanzashi/scripts/hair_penetration.py -- list
```

体・腕・脚・尾など、髪が入ってはいけない**閉じたメッシュ**を選びます。頭は選びません（根元は頭に乗っているのが普通です。各毛束の根元の 5 cm も、初めから数えません）。服や飾りは、ユーザーが気にしているときだけ足します。どれが体か迷うときは、候補を示してユーザーに聞きます。

```bash
blender -b model_k3.blend --python <repo>/skills/kanzashi/scripts/hair_penetration.py -- check --against Body Arm --report pen.json --render-dir pen_img
```

`strands` に、入っている毛束が深い順に並びます。

| 項目 | 意味 |
|---|---|
| `wire` | 毛束（ワイヤー）の番号。パネルの色の一覧の番号と同じ |
| `kind` | `tip`＝毛先が入っている、`through`＝途中が入って先でまた出ている |
| `depth_max_mm`・`buried_cm2` | いちばん深い所の深さ、入っている面積 |
| `along` | 毛束のどの範囲か（0＝根元、1＝毛先） |
| `warnings` | 相手のメッシュが閉じていないとき。開いた所の近くの結果は当てになりません |

画像は、入っている毛束が赤、相手が茶色です。`spot*.png` は、深い所の寄りです。エージェントも画像を見て、数と合っているかを確かめます。

入っている毛束が無ければ、そう伝えて次へ進みます。あるときは：

★ 一覧（毛束の番号・深さ・毛先か途中か）と画像を見せて聞きます。「体に入っている毛束が N 本あります。どう直しますか」。

| 選択 | すること |
|---|---|
| 自分で直す | 手順 3 と同じく、ユーザーが Blender で ④ のつまみを動かして直す。直す毛束の番号を伝える。保存されたら、もう一度 `check` を行う |
| AI の案で直す | 下の「AI が直す」 |
| このままでよい | 何もしない。報告に「貫通 N 本をそのままにした」と書く |

**AI が直す**：先に、案を言葉で示します。「ワイヤー 6・0・30 を外へ 15〜30 mm 動かします。ワイヤー 40 は深さ 26 mm あるので動かさず、残します」。深さが `--max-depth-mm`（既定 25）を超える毛束は、動かす量が大きく、形が変わりすぎるので、自動では動かしません。ユーザーが曲げるか、通し直すかを決めます。

```bash
blender -b model_k3.blend --python <repo>/skills/kanzashi/scripts/hair_penetration.py -- fix --against Body Arm --out model_k3b.blend --report fix.json --render-dir fix_img
```

- ワイヤーを、深さより少し多く外へ、ワイヤーに沿ってなめらかに動かします。ユーザーがつまみを動かしたのと同じ結果になり、後から手で直せます。
- 報告の `wire_moved_mm`（ワイヤーの動いた量）、`hair_moved_max_mm`（髪の頂点の動いた量の最大）、`still_buried`（まだ入っている）、`new_buried`（新しく入った）、`left_for_the_user`（動かさなかった）を読みます。
- 画像は、動かした毛束が青、まだ入っている毛束が赤です。`all_*.png` で、髪の形が崩れていないかを見ます。

★ 直した後の画像と数を見せて聞きます。「この直し方でよいですか」。よければ `model_k3b.blend` を次へ使います。よくなければ、`model_k3.blend` に戻り（そのまま残っています）、ユーザーが直すか、`--wire 番号` で毛束を絞ってやり直します。

調べるのは、ファイルの今の姿勢だけです。腕を動かした姿勢や、髪どうしの重なりは調べません。

### 6. UV の使い道

★ 聞きます。「髪の UV をどう使いますか」。

| 選択 | すること |
|---|---|
| テクスチャを作り直す | `--export hair.fbx` を付けて実行。毛束ごとの UV だけを持つ髪が出ます。作り直したテクスチャをどう戻すかは、ユーザーと決めます。**Tripo でテクスチャを作るときは、髪に Smart UV を使わない**（下の注意） |
| 今の見た目のまま、新しい UV に替える | `--swap` を付けて実行。今のテクスチャを新しい UV へ写します。報告の `swap` に、色が違う三角形の数が出ます |
| UV だけ足しておく | 何も付けない。UV マップ `LW_StrandUV` が足され、今の描画は変わりません |

```bash
blender -b model_k3.blend --python <repo>/scripts/kanzashi_run.py -- --out model_k4.blend --swap --report k4.json
```

**注意（必ずユーザーに伝える）：Tripo で髪のテクスチャを作るとき、Smart UV を使わない。** Smart UV は UV を作り直すので、毛束ごとの UV が消えます。書き出した髪を渡すときは、元の UV を保つ設定で行うよう、書き出しの報告と一緒に伝えます。戻ってきたモデルは、UV の島の数と配置が書き出した物と同じかを確かめてから使います。違っていたら、Smart UV が掛かっています。使わずにユーザーへ知らせます。

### 7. 形の確定

曲げる仕組み（ワイヤーとモディファイア）は、ファイルに残しておけば後で続きができます。

★ 書き出し（FBX・VRM など）の前、またはユーザーが「髪はもう曲げない」と言ったときに聞きます。「曲げた形をメッシュに書き込んで、ワイヤーを外してよいですか。外した後にまた曲げるには、検出からやり直しになります」。よければ `--apply` を付けて実行します。毛束ごとの色と UV は残ります。

### 8. 制作のファイルへ戻す

出来たファイルは、元のファイルの写しに髪の変更が入った物です。元のファイルを置き換えるか、別の版として残すかは、ユーザーの決まりに従います。こちらから上書きしません。

## 報告に書くこと

- どのファイルから、どのファイルを作ったか。
- 毛束の数、UV の島の数、検査の結果（`check.ok` と、重なる面・つぶれた面の割合）。
- 貫通を調べた相手、入っていた毛束の数、直し方（ユーザー／AI／そのまま）と、直した後の数。
- ユーザーが確認した所と、その答え。
- 確かめていないこと（例：リグを動かした確認、書き出した先での見え方）。

## 分かっている限界

- 試作です。Blender 5.3、Windows でしか試していません。
- 塗りは面ごとです。面より細かくは塗れません。
- 板のような前髪、細い面、平らに開きにくい形では、検出が粗くなったり、UV の島が毛束の数よりずっと多くなったりします。
- 枝分かれした毛束のワイヤーは、親のワイヤーに付いて動きません。
- 塗り直しは、曲げる前に行います。
- 張り替えで写すのは、UV で読む画像だけです（MatCap などは写しません）。
- シェイプキーのある髪では試していません。
- 処理中は Blender の画面が止まります。長い髪で数十秒から数分かかります。背景実行は時間の上限を長めに取ってください。
